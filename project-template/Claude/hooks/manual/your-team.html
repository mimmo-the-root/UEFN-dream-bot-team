Your team

Seventeen agents, each with one narrow job, so that the one who writes is never the one who approves.

You do not need to remember all of them. In day-to-day work you talk to Claude, and it calls the right agent. You can also ask for one by name.

How to call an agent

  • In plain words: use the coder agent to add the respawn checkpoint.
  • By name, which guarantees the hand-off: @"coder (agent)" add the respawn checkpoint.
  • Or just describe the task. Claude can pick the agent from each one's description.

The path of one task

Every change follows the same five stages, shown live on the console:

  1. planner-docs opens a task in the roadmap with its acceptance criteria.
  2. intent-gate checks that the task is concrete enough to build without guessing.
  3. coder writes the code and compiles it.
  4. intent-reviewer checks that the result matches the acceptance criteria, line by line.
  5. compliance-reviewer checks the kit's mechanical rules: logging, naming, multiplayer authority and so on. Only then does planner-docs mark the task Done.
Note

The coder never closes its own task. Two independent reviewers must pass it first.

The agents and their models

Cost matters. The kit puts the cheaper model on work that is mostly checking or bookkeeping, and the stronger one where judgment and code are needed.

AgentModelWhat it does
project-bootstrapSonnetUse once, at the start of a project: maps existing code or asks the questions for a new one.
planner-docsHaikuOwns the roadmap and the status. Opens and closes tasks.
intent-gateHaikuChecks the task is clear before any code is written.
coderSonnetWrites and fixes code, in a compile and fix loop.
coder-prepSonnetInternal helper: writes one independent area of code in parallel.
intent-reviewerSonnetFirst review gate: does it do what the task asked?
compliance-reviewerHaikuSecond review gate: does it follow the kit's rules?
qa-regressionSonnetFinds regressions and unseen bugs after changes and playtests.
release-gateSonnetGo or no-go before a release, from the project's own documents.
codebase-auditorSonnetIndependent audit of the whole codebase, on demand.
skill-reflectorHaikuProposes lessons for your genre after a real playtest.
growth-managerSonnetEverything about getting the map found and played: titles, thumbnails, trailers, launch plans.
materials-expertSonnetAudits and reuses materials in the project.
template-readerSonnetReads an Epic template, read only.
second-brain-librarianSonnetOptional: keeps a shared Obsidian vault of reusable mechanics.
second-brain-trainerSonnetOptional: a deliberate sweep of the project to fill that vault.
second-brain-scoutHaikuInternal helper of the trainer: analyses one area, read only.

Haiku is the lighter, cheaper model; Sonnet is the stronger one. No agent uses Opus.

Tip

Agents that only check keep their reports short on purpose: their report lands in your main session, the most expensive place to spend words.

What reports tell you

The audit agents (qa-regression, release-gate, codebase-auditor) end every report with two lines: what they verified and what they did not verify. A pass is never silent about what it did not check.

Overriding an agent for one project

Create an agent with the same name in that project's .claude/agents/ folder. It wins there and only there.
